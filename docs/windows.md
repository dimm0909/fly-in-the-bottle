# Windows

Виджет написан так, чтобы работать на Windows 10/11, но **разработка велась на Linux, и на Windows он ни разу не
запускался**. Эта страница разделяет то, что проверено, и то, что нет, и объясняет, как устроена каждая
Windows-специфичная часть, чтобы её можно было быстро починить, если что-то ведёт себя иначе.

## Что проверено

| Часть | Статус |
| --- | --- |
| Сайдкар мозга собирается под Windows | Проверено: кросс-сборка `zig c++ -target x86_64-windows-gnu` даёт `PE32+ executable (console) x86-64` без предупреждений в наших исходниках. **Исполняемый файл не запускался** (Wine на машине разработки нет). |
| Формат `graph.bin` не зависит от компилятора | Проверено: заголовок с `#pragma pack(push, 1)` и `static_assert(sizeof(GraphHeader) == 20)`; на Linux граф читается без изменений. |
| Логика `tools/dev.js` на Linux | Проверено: `start`, `compile-brain` (g++ и zig), `brain:check`, `docs`, построение графа. Загрузка данных с нуля на этой машине не прогонялась (файлы уже были), ветки Windows (`.exe`, `Scripts\python.exe`, `py -3`, `cl`) прочитаны, но не выполнялись. |
| Окно-инструмент, `SetWindowPos`, `koffi` | Не проверялось. |
| Прозрачность и полёт кадров под другими окнами | Не проверялось. |
| Колесо мыши на окне без фокуса | Не проверялось. |
| Звук (`silence()` при скрытии страницы) | Логика проверена на Linux; событие `visibilitychange` на Windows не проверялось. |

Если вы запустите виджет на Windows, самое полезное, что можно сообщить: удалось ли `npm start`; видно ли окно;
лежит ли оно под окнами и что происходит по `Win+D`; принимает ли клики и колесо; собрался ли `brain.exe`
(`npm run brain:check`).

## Быстрый старт на Windows

В PowerShell или `cmd` из каталога проекта:

```powershell
npm install
npm start                # виджет на запасной сценарной мухе

npm run brain:setup      # по желанию: скачать коннектому и собрать мозг
npm run brain:check
npm start
```

Нужны Node.js и, для мозга, Python 3 (`py -3` или `python` в `PATH`). Компилятор ставить не обязательно: если нет
`g++`, `c++`, `clang++` и `cl`, команда `brain:setup` установит `ziglang` из PyPI (около 80 МБ) и соберёт
`data\brain\brain.exe` им. Используется MinGW/MSYS2 `g++` со статической линковкой (`-static`) или MSVC с `/MT`:
в обоих случаях `brain.exe` не требует сторонних DLL. `cl` находится, только если он есть в `PATH` (например,
в «Developer Command Prompt»).

## Слой «на обоях»

У Windows нет типа окна «рабочий стол», как у X11. Ближайшее, что удалось придумать, - `platform.js`:

1. Конструктор окна получает `type: 'toolbar'` и `focusable: false` (стили `WS_EX_TOOLWINDOW` и
   `WS_EX_NOACTIVATE`): окно не забирает фокус, клик по нему не поднимает его наверх и его нет в Alt-Tab. Панель задач
   пропускается опцией `skipTaskbar`.
2. После показа окно прижимается ко дну порядка окон вызовом `SetWindowPos(hwnd, HWND_BOTTOM, …)` с флагами
   `SWP_NOSIZE | SWP_NOMOVE | SWP_NOACTIVATE | SWP_NOOWNERZORDER`, и то же повторяется каждые 2 секунды: другие
   программы могут перетасовать порядок.
3. Вызов идёт через необязательный пакет `koffi` (`user32.dll`, без компиляции: пакет приносит готовые бинарники).
   Если `koffi` не установился или вызов не удался, в лог попадает предупреждение (`desktop layer: cannot reach
   user32 …`), а виджет остаётся обычным окном-инструментом.

Слои `normal` и `top` на Windows ведут себя как на других системах. Если «на обоях» работает плохо (виджет
перекрывает окна или, наоборот, пропадает после `Win+D`), выберите в меню «Положение → Обычное окно» или запустите
с `--layer=normal`.

Чего в этом слое нет и на что стоит обратить внимание:

- `Win+D` («показать рабочий стол») сворачивает окна; что она делает с окном-инструментом ниже всех, не проверялось;
- `HWND_BOTTOM` кладёт окно на дно порядка окон; окажется ли оно при этом над самим рабочим столом (обоями и значками,
  которые рисует оболочка), а не за ним, не проверялось. Если банки не видно даже на пустом столе, выберите слой
  «Обычное окно»;
- виртуальные рабочие столы Windows: `setVisibleOnAllWorkspaces` на Windows не применяется, поведение по столам не
  проверялось.

## Что ещё отличается на Windows

| Что | Как учтено |
| --- | --- |
| Песочница Chromium | `--no-sandbox` добавляется только на Linux; на Windows песочница остаётся включённой. |
| Прозрачность | Флаг `enable-transparent-visuals` нужен и ставится только на Linux; на Windows окно с `transparent: true` получает альфа-канал само. |
| Закрытые окна не рисуются | Chromium на Windows перестаёт рисовать окно, которое считает полностью перекрытым (`CalculateNativeWinOcclusion`; это поведение Chromium, здесь не наблюдалось). Это как раз полезно: виджет под окнами не тратит процессор. Но жужжание в этот момент нечем гасить, поэтому страница на `visibilitychange` вызывает `Sound.silence()`. В режиме `--shot` этот механизм отключается переключателем `disable-features=CalculateNativeWinOcclusion`, иначе окно за экраном не анимируется. |
| Имя сайдкара | `data\brain\brain.exe`; `brain-host.js` и `tools/brain_client.py` выбирают его по `process.platform` / `sys.platform`. |
| Окно консоли сайдкара | Не появляется: процесс запускается с `windowsHide: true`. |
| Концы строк | Хост режет ответы по `\n` и обрезает пробелы (в том числе `\r`); сайдкар читает команды через `std::getline`; `groups.txt` пишется с `\n`. |
| Пути | Везде `path.join` / `pathlib`; `asset:read` проверяет выход за `assets/` с разделителем платформы. |
| Скрипты | Всё через `node tools/dev.js`: `bash`, `make`, `curl` и `.venv/bin/…` не нужны. |
| Файл настроек | `%APPDATA%\fly-in-the-bottle\settings.json` по правилам Electron (не проверялось). |
