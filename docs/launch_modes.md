# Режимы запуска

Все режимы стартуют из одного `main.js`; различаются npm-скриптом и флагами командной строки.

## npm-скрипты

Все скрипты идут через `tools/dev.js` - кроссплатформенный помощник на Node (Linux, Windows, macOS): он не зависит
от `bash`, `make` и путей вида `.venv/bin/python`.

| Скрипт | Команда | Когда использовать |
| --- | --- | --- |
| `npm start` | `node tools/dev.js start` | Обычный запуск: `electron .` (на Linux с `--no-sandbox`, без `ELECTRON_RUN_AS_NODE`). Мозг стартует, если он установлен и включён в настройках. |
| `npm run start:scripted` | `node tools/dev.js start --no-brain` | Принудительно запасная сценарная муха. |
| `npm run shot` | `node tools/dev.js start --shot` | Рендер одного кадра в PNG без показа окна на экране (см. ниже). |
| `npm run brain:setup` | `node tools/dev.js setup-brain` | Один раз: скачать коннектому, построить граф и группы, собрать мозг. |
| `npm run brain:compile` | `node tools/dev.js compile-brain` | Только пересобрать симулятор `data/brain/brain[.exe]`. |
| `npm run brain:check` | `node tools/dev.js py tools/check_brain.py` | Проверить собранный симулятор. |
| `npm run docs` | `node tools/dev.js docs` | Собрать эту документацию (полная пересборка). |

Команда `node tools/dev.js py <скрипт> [аргументы]` запускает любой скрипт из `tools/` интерпретатором `.venv`
(`.venv/bin/python` или `.venv\Scripts\python.exe`), так что в примерах документации вместо
`.venv/bin/python tools/…` на Windows можно писать `node tools/dev.js py tools/…`.

## Флаги командной строки

Всё после `--` в `npm start -- …` попадает в Electron. Флаги приложения читает `main.js`; флаги Chromium
(`--no-sandbox` и др.) обрабатывает сам Electron. Если флаг повторён (`npm run shot -- --shot=файл.png`, а
скрипт уже добавил голый `--shot`), действует **последний**.

| Флаг | Значение |
| --- | --- |
| `--no-sandbox` | Отключает песочницу Chromium; `npm start` добавляет его сам, но только на Linux: без него на Ubuntu 24.04 окно остаётся пустым, см. [quickstart](quickstart.md). |
| `--no-brain` | Не запускать мозг в этом запуске (сохранённая настройка не меняется). |
| `--layer=desktop\|normal\|top` | Переопределяет сохранённый слой окна только на этот запуск. |
| `--dev` | Отдаёт странице объект `window.__w` (сцена, муха, банка, мозг…) и включает отладочный лог указателя. |
| `--shot[=файл.png]` | Режим скриншота: отрисовать, сохранить PNG с альфа-каналом и выйти. По умолчанию `shots/shot.png`. |
| `--script=файл.js` | Только с `--shot`: JS, выполняемый в странице до снимка; его результат печатается в лог. |
| `--delay=мс` | Только с `--shot`: пауза перед снимком после скрипта (по умолчанию 1500). |

```{warning}
Не используйте флаг `--debug`: Node считает его флагом отладчика и завершает процесс с кодом 9.
Для этого и введён `--dev`.
```

## Слои окна

Слой на конкретной системе задаёт `platform.js` (подробности и что проверено: [windows](windows.md)).

| Слой | Linux (X11) | Windows | Замечания |
| --- | --- | --- | --- |
| `desktop` (по умолчанию) | Тип окна `_NET_WM_WINDOW_TYPE_DESKTOP`: под всеми остальными, на всех рабочих столах, скрыто из панели задач и Alt-Tab. | Окно-инструмент без фокуса (`type: 'toolbar'`, `focusable: false`), которое каждые 2 секунды прижимается ко дну порядка окон через `SetWindowPos(HWND_BOTTOM)`. | Виджет не виден, пока рабочий стол закрыт окнами. Тип нельзя сменить у живого окна, поэтому смена слоя пересоздаёт окно. |
| `normal` | Обычное окно без рамки. | То же. | Удобно для разработки. |
| `top` | Поверх всех окон (`setAlwaysOnTop(true, 'screen-saver')`). | То же. | Мешает работе, но банку всегда видно. |

На macOS слоя «на обоях» нет: `desktop` там ведёт себя как `normal` (не проверялось).

Окно всегда `frame: false`, `transparent: true`, без тени и без изменения размера пользователем, показывается через
`showInactive()` (не забирает фокус). На Linux включён переключатель Chromium `enable-transparent-visuals`: без него у
окна не будет альфа-канала.

## Масштаб

Окно сохраняет пропорцию 0,72 (базовый размер, масштаб 100%: 360×500), чтобы сцена масштабировалась равномерно.
Масштаб - число от 0,5 до 3; меняют его колесом мыши (см. [controls](controls.md)) или пунктом меню «Размер».

| Пресет меню | Масштаб | Пиксели |
| --- | --- | --- |
| Маленький (S) | 0,8 | 288×400 |
| Средний (M, по умолчанию) | 1 | 360×500 |
| Большой (L) | 1,3 | 468×650 |

Предел 3 (1080×1500) достижим только на экране, где окно помещается: масштаб дополнительно ограничивается размером
рабочей области (97% от высоты или ширины экрана). Позиция окна при смене масштаба зажимается в эту область (в режиме
`--shot`, где окно за экраном, не зажимается).

## Файл настроек

`~/.config/fly-in-the-bottle/settings.json` на Linux (на Windows по правилам Electron это `%APPDATA%\fly-in-the-bottle\settings.json`;
на Windows не проверялось): каталог `userData` Electron, файл создаётся при первом сохранении.

| Ключ | По умолчанию | Значение |
| --- | --- | --- |
| `x`, `y` | `null` | Положение окна; `null` - правый нижний угол основного экрана. Хранится при отпускании крышки и в меню. При загрузке положение зажимается в пределы доступных мониторов. |
| `scale` | `1` | Масштаб виджета, от 0,5 до 3. Старый ключ `size` (`"S"`, `"M"`, `"L"`) при загрузке переводится в масштаб 0,8, 1 или 1,3 и удаляется. |
| `layer` | `"desktop"` | `desktop`, `normal` или `top`. |
| `sound` | `true` | Включён ли звук. |
| `brain` | `true` | Включён ли мозг (действует, если он установлен). |

Разрешён один экземпляр: повторный запуск просто показывает уже запущенное окно
(`requestSingleInstanceLock`).

## Режим скриншотов и тестовый стенд

`--shot` - основной инструмент разработки. Он нужен, чтобы получать кадры и проверять поведение, не
трогая рабочий стол.

1. Окно создаётся у `x=-5000, y=-5000`, за пределами экрана, и делается прозрачным для мыши
   (`setIgnoreMouseEvents(true)`). Скрытое (`show: false`) окно не годится: у него `requestAnimationFrame`
   срабатывает примерно раз в секунду, и анимация не идёт.
2. Настройки не читаются и не сохраняются (`saveSettings()` в режиме скриншота ничего не пишет); нативное
   меню не открывается.
3. Стенд ждёт до 10 секунд, пока страница построит сцену (`window.__w`): загрузка ассетов и прогрев мозга
   асинхронны.
4. Если задан `--script`, файл выполняется в главном мире страницы (`executeJavaScript`). Если он
   возвращает значение (например, `async`-функцию), результат печатается строкой `script result: {...}`;
   после него печатаются границы окна `bounds: {...}`.
5. Через `--delay` мс делается `capturePage()` и сохраняется PNG **с прозрачностью**; процесс выходит.

Пример: тычок по мухе и снимок.

```js
// poke.js
(async () => {
  const w = window.__w;
  w.fly.touch('c_head', 0);
  await new Promise((r) => setTimeout(r, 800));
  return { state: w.fly.state, power: w.fly.power };
})()
```

```bash
npm run shot -- --shot=shots/poke.png --script=poke.js --delay=200
```

Скрипт `npm run shot` сам добавляет голый `--shot`, а поздний `--shot=файл` его переопределяет. Масштаб проверяется
так же: `window.widget.zoom(1.5)` внутри скрипта меняет размер окна, а `bounds: {...}` в выводе покажет результат.

Больше примеров и подводные камни: [development](development.md).
